# Отчёт: Traci

## Предметная область

Traci — приложение для отслеживания просмотра фильмов. Пользователь регистрируется, входит в аккаунт, просматривает каталог с поиском, фильтрами и пагинацией. В личной коллекции он добавляет и удаляет фильмы, меняет статус просмотра, оценку и отзыв. Администратор создаёт, читает, изменяет и удаляет фильмы каталога, просматривает пользователей, блокирует и удаляет аккаунты.

Приложение состоит из веб-интерфейса, HTTP-бэкенда и PostgreSQL. CRUD реализован для фильмов и записей личной коллекции.

## Стек реализации

Бэкенд написан на Go 1.25: стандартный HTTP-сервер, REST/JSON, pgx/v5, Viper, JWT и golang-migrate/v4. SQL-запросы генерируются sqlc, модели, клиент и сервер API — oapi-codegen из OpenAPI. Пароли хранятся как PBKDF2-SHA256-хеши с индивидуальной солью.

Фронтенд использует HTML, CSS и JavaScript без фреймворка. nginx раздаёт статические файлы и проксирует `/api/` в бэкенд. Node.js требуется только для тестов. Docker Compose запускает PostgreSQL, одноразовый мигратор, бэкенд и фронтенд.

Код бэкенда разделён на domain, application, infrastructure, transport, repository и config. Интерфейсы репозиториев находятся в domain, реализации — в `backend/internal/repository/sql`.

## Основные сущности

| Сущность | Назначение |
|---|---|
| `User` | Аккаунт пользователя, роль и состояние блокировки |
| `Movie` | Фильм: название, описание, год, продолжительность и жанры |
| `CollectionItem` | Связь пользователя с фильмом: статус просмотра, оценка и отзыв |

Каталог представляет собой выборку фильмов, отдельная сущность для него не нужна. Пользователь работает только со своей коллекцией; управление фильмами и пользователями доступно администратору.

## Запуск через Docker Compose

Команды выполняются из корня проекта. Нужны Docker с Compose и GNU Make. Go, sqlc и Node.js для этого способа запуска на хосте не требуются.

```sh
cp backend/.env.example backend/.env
```

Шаблон содержит только имена переменных, без значений. Перед запуском заполните `backend/.env` своими настройками. Если файл уже существует, используйте его, не перезаписывая текущие параметры.

| Переменная | Назначение |
|---|---|
| `POSTGRES_DB` | Имя базы, создаваемой контейнером PostgreSQL |
| `POSTGRES_USER` | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `POSTGRES_URL` | URL подключения, соответствующий указанным базе, пользователю и паролю; в Compose хост — `db`, порт — 5432 |
| `JWT_SECRET` | Секрет подписи JWT длиной минимум 32 байта |
| `HTTP_ADDR` | Адрес сервера при запуске без Compose; в Compose приложение слушает `:8080` |
| `HTTP_PORT` | Публикуемый порт бэкенда; по умолчанию 8080 |
| `FRONTEND_PORT` | Публикуемый порт фронтенда; по умолчанию 3000 |
| `BACKEND_URL` | Адрес бэкенда для nginx; в Compose по умолчанию `http://app:8080` |
| `TOKEN_TTL` | Срок действия JWT; по умолчанию `1h` |
| `CONNECT_TIMEOUT` | Таймаут подключения к БД; по умолчанию `5s` |
| `SHUTDOWN_TIMEOUT` | Время корректного завершения HTTP-сервера; по умолчанию `10s` |
| `STOP_GRACE_PERIOD` | Время завершения контейнера; по умолчанию `15s`, должно превышать `SHUTDOWN_TIMEOUT` |

Обязательны первые пять переменных. Неиспользуемые необязательные строки можно удалить: для запуска без Compose пустое значение таймаута или адреса может перекрыть значение по умолчанию. Секрет можно получить командой `openssl rand -hex 32`. Реальные значения `.env` не включаются в исходники, образ и архив.

```sh
make docker-up
curl http://localhost:8080/healthz
```

Compose сначала запускает базу, затем применяет миграции и запускает приложение. Миграции встроены в бинарник бэкенда; мигратор использует тот же образ и `POSTGRES_URL`. Повторный запуск не применяет выполненные миграции заново.

Откройте http://localhost:3000 и зарегистрируйтесь. `localhost` в браузере означает компьютер с опубликованными портами. Внутри контейнеров службы обращаются друг к другу по именам `db` и `app`.

Администратор создаётся отдельной командой:

```sh
make create-admin
```

Введите новые никнейм, имя, фамилию, почту и пароль. Пароль в интерактивном терминале скрыт. Команда использует application и репозиторий, создаёт роль `admin` и хеширует пароль. При занятой почте или никнейме существующий аккаунт не изменяется. Обычная регистрация создаёт роль `user`.

```sh
make docker-down
```

Остановка сохраняет данные PostgreSQL в volume. Изменение переменных базы не меняет автоматически пароль или имя уже созданной базы. Команду `down --volumes` для обычной остановки использовать не нужно: она удаляет данные.

## Сборка и запуск без Docker

Нужны Go 1.25 и PostgreSQL 17 с правом создания расширения `pg_trgm`. Настройте `backend/.env` или переменные окружения; `POSTGRES_URL` должен указывать на базу, доступную с хоста. Переменные окружения имеют приоритет над необязательным `.env`.

```sh
make build
cd backend
./bin/traci migrate
./bin/traci serve
```

Для администратора используйте `./bin/traci create-admin`. Миграции не выполняются автоматически при запуске HTTP-сервера.

Сгенерированный код находится в `backend/internal/gen` и входит в исходники. Для повторной генерации установите sqlc v1.31.1 и выполните `make generate`. Версия oapi-codegen закреплена в `backend/go.mod`. Контракт API — `docs/api/openapi.yaml`, схема базы — `docs/db/schema.dbml`.

## Соответствие 12 факторам

Описание относится к текущему коду и основному Docker Compose. Все факторы применимы; ограничения реализации указаны явно.

| Фактор | Реализация |
|---|---|
| 1. Кодовая база | Одна кодовая база в одном Git-репозитории. Бэкенд, фронтенд, миграции и документация находятся в одном проекте. Архив передаёт снимок исходников. |
| 2. Зависимости | Go-зависимости закреплены в `go.mod`/`go.sum`, тестовые зависимости фронтенда — в `package-lock.json`. Версия генератора oapi-codegen закреплена, версия sqlc указана в инструкции. Базовые Docker-образы закреплены digest. |
| 3. Конфигурация | Конфигурация приходит из окружения с поддержкой необязательного `.env`. URL базы и JWT-секрет не зашиты в код. `.env.example` перечисляет переменные без значений. |
| 4. Внешние службы | PostgreSQL — внешний ресурс, подключаемый по `POSTGRES_URL`. Смена адреса базы выполняется настройками, а не изменением кода. |
| 5. Сборка, релиз, запуск | Dockerfile разделяет компиляцию и исполняемый образ; настройки передаются при запуске. Compose допускает тег через `RELEASE_ID`. Автоматической фиксации релизов нет: обычный `make docker-up` собирает изменяемый тег `local`. Для версионированного релиза нужно отдельно задать новый ID, собрать образ и запускать его без пересборки. |
| 6. Процессы | HTTP-процесс не хранит пользовательские данные и серверные сессии локально. Данные и роли находятся в PostgreSQL, а JWT проверяется с общим секретом. |
| 7. Привязка портов | Go-процесс самостоятельно слушает HTTP-порт; адрес локального сервера и публикуемые порты задаются конфигурацией. API использует HTTP/JSON и поддерживает HTTP/1.1. |
| 8. Масштабирование | Архитектура позволяет несколько экземпляров с общей БД и JWT-секретом. Текущий Compose запускает один бэкенд и один фронтенд: фиксированные имена и порты не позволяют масштабировать их командой `--scale`. Балансировщик и конфигурация нескольких реплик в сдаваемый проект не входят. |
| 9. Одноразовость | SIGINT/SIGTERM запускают ограниченный по времени HTTP Shutdown, затем закрывается пул БД. Compose предоставляет дополнительное время через `stop_grace_period`. |
| 10. Паритет окружений | Compose позволяет использовать одни и те же образы для разработки и запуска. Интеграционные тесты используют PostgreSQL 17 с тем же digest. При запуске без Docker версию PostgreSQL нужно поддерживать самостоятельно. |
| 11. Логи | Go пишет JSON-логи в stdout, nginx — в stdout/stderr. Хранение и сбор логов выполняет окружение, собственные лог-файлы приложение не создаёт. |
| 12. Административные процессы | Миграции и создание администратора выполняются командами `traci migrate` и `traci create-admin` из того же образа приложения. SQL-миграции встроены в бинарник. |

Для отдельной сборки и запуска конкретной версии можно использовать обычные команды Compose, без дополнительных файлов:

```sh
export RELEASE_ID=<идентификатор-версии>
docker compose --env-file backend/.env build
docker compose --env-file backend/.env up --no-build -d --wait
```

Для каждого изменённого исходного кода нужен новый ID. Чтобы вернуться к ранее сохранённым образам, укажите их ID и выполните запуск без пересборки. Совместимость предыдущего приложения с текущей схемой базы проверяется отдельно; автоматического отката схемы нет.

Описание факторов: [12factor.net](https://12factor.net/).

## Проверки

```sh
make test-unit
make test
make test-race
```

Тесты используют testify. Полный запуск требует Docker: интеграционные проверки поднимают отдельные PostgreSQL через testcontainers, применяют миграции и удаляют тестовые контейнеры. `make test-unit` пропускает проверки с PostgreSQL.

Интеграционные тесты находятся рядом с кодом:

- `backend/db/postgres/postgres_test.go` — пул и миграции;
- `backend/internal/repository/sql/repository_test.go` — репозитории;
- `backend/internal/transport/http/integration_test.go` — HTTP API с БД;
- `backend/internal/infrastructure/app_test.go` — запуск и завершение приложения, создание администратора.

Общий помощник запуска PostgreSQL: `backend/internal/testutil/postgres.go`.

Тесты фронтенда:

```sh
cd frontend
npm ci
npx playwright install chromium
cd ..
make test-frontend
make test-e2e
```

Браузерный сценарий требует запущенного приложения и проверяет регистрацию, вход, CRUD фильмов, коллекцию, блокировку пользователя и мобильный интерфейс. Скрипт `./check-backend.sh` проверяет API, создавая уникальные тестовые данные и удаляя их после завершения.

## Состав архива

Для сдачи используется ZIP с полными исходниками бэкенда и фронтенда, сгенерированным кодом, миграциями, тестами, Dockerfile, основным Compose, документацией и этим `Отчёт.md`.

В архив не входят настоящий `.env`, `.git`, `node_modules`, собранные бинарники и результаты тестов. `.env.example` содержит только названия переменных. Специальный скрипт упаковки не требуется.
